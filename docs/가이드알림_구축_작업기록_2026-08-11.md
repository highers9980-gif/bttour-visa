# 가이드 알림(카카오 알림톡) 구축 작업기록 — 2026-08-11

ERP에서 가이드에게 지시서·공지를 카카오 알림톡으로 보내고, 열람 여부까지 추적하는 기능.

---

## 왜 알림톡인가

| 후보 | 판단 |
|---|---|
| 잘로 봇 | **불가** — Zalo Bot Platform 은 `sendMessage`/`sendPhoto` 만 있고 파일 전송 API가 없다 |
| 카카오 친구톡 | **불가** — 2025-12-31 종료, 2026-01-01 부터 브랜드메시지로 대체 |
| 카카오 알림톡 | **채택** — 전화번호만 있으면 간다. 채널 친구 여부 무관, 가이드가 할 일 없음 |

가이드 대부분이 베트남계라 텔레그램·잘로 재교육이 부담이었고, 알림톡은 **가이드 쪽 액션이 0**이다.

알림톡의 제약: 파일 첨부 불가, 이미지는 템플릿 고정. 그래서 **본문은 승인된 문구, 실제 내용은 웹 링크 버튼**으로 나간다.

---

## 구성

```
ERP 화면(Vercel)
  └ /api/settlement-bot/*  (BFF: 사이트 로그인 + 관리자 PIN 검증)
      └ Cloudflare Tunnel
          └ settle-gateway (WSL, 127.0.0.1:3600)
              ├ guide-notify.mjs   명부·발송큐·문서보관
              ├ settlement.db      guides / guide_notifications / guide_documents
              └ SOLAPI             카카오 알림톡 발송
```

문서(지시서 HTML·티켓 이미지)는 **게이트웨이가 직접 보관하고 서빙**한다.
`GET /d/<32자리난수>.<확장자>` — PWA를 이미 이 게이트웨이가 서빙하므로 별도 스토리지를 두지 않았다.

**템플릿 ID는 웹에 두지 않는다.** 화면은 위 `key` 만 보내고 게이트웨이의 `TEMPLATE_IDS` 표가 ID로 바꾼다.
반려 후 재등록으로 ID가 바뀌어도 게이트웨이 파일만 고치면 되고 ERP 재배포가 필요 없다.

버튼 링크는 전부 `https://cdn.for-bt.com/d/#{문서키}`. **도메인은 고정, 경로만 변수** — 전체 URL을 변수로 두면 심사에서 반려된다.

## 명부

`2026-03 ~ 2026-10` 일정현황에서 자동 수집. 22명 확보.

- **한글이름** — `ScheduleTeam.guide`
- **베트남이름** — `raw` 의 `##META##.guide_rows`, 없으면 `Mr./Ms.` 표기
- **연락처** — `##META##.guide_rows` 중 휴대폰 형태, 없으면 `||` 로 나뉜 **3번째 구간(GUIDE 열)** 의 첫 `010` 번호

### 주의해서 짠 부분

1. **2번째 구간은 DRIVER 열이라 절대 안 쓴다.** 기사 번호를 가이드로 넣으면 지시서가 기사에게 날아간다.
2. **한 칸에 두 명(`김유미/타오`)이면 번호를 배정하지 않는다.** 누구 것인지 확정할 수 없다.
3. **사람을 가리는 열쇠는 연락처다.** 이름은 `민 다오`/`민다오` 처럼 흔들리지만 번호는 하나다. 번호로 먼저 찾고 없을 때만 이름으로 잇는다.
4. `guides.phone` 에 **부분 유일 인덱스**를 걸어 같은 번호로 두 행이 생기지 못하게 막았다.
5. `guides` 는 원래 카카오 챗봇 테이블이라 `kakao_user_id` 가 `NOT NULL UNIQUE`. ERP로 넣는 사람은 카카오 ID가 없으므로 `phone:01012345678` 을 넣는다 — 이름이 바뀌어도 값이 그대로라 두 번 돌려도 행이 안 늘어난다.
6. `픽업:최성민` 같은 역할 접두어를 떼고, `ONLY HOTEL` 처럼 사람이 아닌 표시는 걸러낸다.

### 구분

- **직원** — 박수현, 양보유, 김유미, 김다솜 (행사 배정과 무관하게 늘 수신)
- **가이드** — 기간 내 배정 있음
- **미배정** — 이름만 남아 있음 (양지원·완태록·원윤아·정희연·타오·투안)

## 삽질 기록 (같은 실수 반복 방지)

| 증상 | 원인 | 교훈 |
|---|---|---|
| `requestInspectionKakaoAlimtalkTemplate is not a function` | solapi SDK에 없는 메서드 | 취소 엔드포인트에서 역산 → `PUT kakao/v2/templates/{id}/inspection` |
| 심사요청 404 | POST로 보냄 | 취소가 PUT이면 요청도 PUT |
| `Cannot find package 'better-sqlite3'` | 게이트웨이는 node 내장 `node:sqlite` 사용 | 의존성 추가 전에 대상 환경 확인 |
| `NOT NULL constraint failed: guides.kakao_user_id` | 카카오 챗봇 테이블 스키마 | `PRAGMA table_info` 로 필수 칸을 읽어 채움 |
| ERP 화면이 계속 데모 | BFF 허용 경로 목록에 `api/admin/guides` 없음 → 404 | 화면이 실패 이유를 숨기면 원인을 못 찾는다 → 배너에 코드 표시 |
| `{"error":"unauthorized"}` | `SETTLE_ADMIN_KEY` ≠ `SETTLEMENT_GATEWAY_ADMIN_TOKEN` | 소문자 `unauthorized` 는 게이트웨이 응답 (BFF는 대문자 코드) |
| 변수가 빈 채로 나갈 뻔 | 화면은 `팀명`, 큐는 `#{가이드명}` 으로 섞임 | `wrapVariables()` 로 통일 |
| `.env` 날림 | `mv` 로 옮기라고 안내 | 설정 파일은 `cp` |

## 남은 것

1. **관리자 키 맞추기** — `node tools/fix-admin-key.mjs` → 찾으면 `--apply`
2. **`cdn.for-bt.com`** — Cloudflare Tunnel 에 공개 호스트명 추가 (`http://127.0.0.1:3600`)
3. **템플릿 승인 대기** — `node create-templates.mjs list` 로 상태 확인

셋 다 끝나면 ERP에서 파일 올리고 → 템플릿 고르고 → 발송이 바로 된다.

## 보안 메모

- 브리핑에는 가이드·기사 연락처, 실명 로밍리스트, KTX 좌석이 들어간다.
  문서 키는 **128비트 난수**, `noindex`·`no-store`·CSP 적용, 90일 만료.
- 기존 `settlement.html?batch=<순번>&key=<공용키>` 방식은 **반복하지 않는다.**
- `/api/guides` (ERP Nest) 가 **인증 없이 열려 있다.** 연락처를 채워 넣었으므로 노출 대상이 커졌다. PIN 헤더를 거는 작업이 필요하다.
- 토큰·키는 채팅에 붙여넣지 않는다. `.env` 는 `chmod 600`, `.gitignore` 확인.
